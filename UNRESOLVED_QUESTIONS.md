# Unresolved questions

## Root storage ACL owner and writer forms

The finite accepted forms of the native owner and writer ACLs have not yet been
selected. Qualification must first record the actual UID, GID, owner type and
complete ACL projection of the fixed public test item, including numeric
authorizations, NULL versus empty application subjects, unreadable requirements
and both prompt representations. Unknown forms remain observations.

The fixed certificate requirement, owning-vault release ACL and partition rule
do not settle this question. Successful creation, matching readback or a foreign
read refusal alone cannot admit an owner or writer form for root-secret storage.
Select and review an explicit compatibility table from attended native evidence
before implementing or qualifying root creation; pair accepted forms with
forbidden and unknown forms. Do not learn an allowlist during production use.

The public qualification interface creates no root and supplies no decision on
this policy. Its receipts, artifact checks and separately attended cleanup retain
their narrower contracts.
